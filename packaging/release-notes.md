# EchoNote v0.12.1 · 桌面化与录音音量

> 技术预览（tech preview），不是 v1.0。录音与识别都在本机完成，音频不上传任何服务器。

## 下载后怎么用（Windows，不需要装 Python）

1. 下载 `EchoNote-v0.12.1-windows-x64.zip`（不含模型）
2. 解压到**任意可写目录**，例如 `D:\EchoNote` —— 不要放在 `C:\Program Files`
3. **双击 `fetch-model.bat`** 准备模型（实时字幕 145 MB + 定稿 1.5 GB，自动走国内镜像，只需一次）
4. 双击 `EchoNote.exe`，会打开一个**独立的应用窗口**（没有地址栏和标签页），点麦克风开始录音
5. 关闭应用窗口即退出；后台进程会在几秒后自行结束

模型放进 `models\` 之后，**识别全程零联网**。需要硬保证不联网的环境：

```
EchoNote.exe --offline
```

### 出问题先跑自检

```
EchoNote.exe --self-test
```

逐项列出原生依赖（ctranslate2 / onnxruntime / av）、前端资源、模型状态。启动失败的日志在
`logs\echonote.log`。

### 想更快：换成 sherpa

默认的 whisper `medium` 定稿准确但慢。这台机器上如果只想「边说边看」，把
`models\asr-backend.txt` 写成 `sherpa`（需要 `models\sherpa-zipformer-zh` 目录），
rtf 从约 0.3 降到 0.126，内存从 1.2 GB 降到 300 MB。

## 这一版改了什么

### 一、像一个软件，而不是一个网页

这一版没有动界面布局，动的是界面**外面**那层壳——用户下载后第一眼看到的东西。

- **独立应用窗口**：用 Edge/Chrome 的 `--app` 打开，没有地址栏、没有标签页、没有书签栏。
  Windows 自带 Edge，不需要额外安装；找不到时按 registry 的 App Paths 继续找，最后回落到
  普通标签页。`ECHONOTE_NO_APP_MODE=1` 可强制回落。
- **不再挂一个黑框控制台**：双击 exe 只剩窗口。但**从 `fetch-model.bat` 启动时控制台保留**——
  用 `GetConsoleProcessList` 判断是否独占控制台，独占才隐藏。一条命令满足两种场景。
- **第二次双击不再开新窗口**：改为把已有窗口调到前台（`SetForegroundWindow`）。
- **自有图标**：任务栏、Alt+Tab、资源管理器都不再是通用图标。图标由
  `packaging/make_icon.py` 纯标准库生成（7 个尺寸，含 256），沿用 favicon 的深蓝 + 青色波形。
- **可以「安装」**：新增 `web/manifest.json`（`display: standalone`），窗口右上角
  「…」→ 应用 → 将此站点作为应用安装，之后开始菜单里有入口。

隐藏控制台带来一个新问题：用户失去了唯一的退出路径。所以补了**关窗即退出**——最后一个页面
断开 6 秒后进程自行结束，前 60 秒有保护期（刷新页面会断连约 1 秒，不能因此误杀）。
`ECHONOTE_NO_IDLE_EXIT=1` 可关闭。

### 二、录音音量

之前录音偏小，是 `getUserMedia` 的 `autoGainControl` 在管。那是给通话调的策略：衰减和放大一样
积极，笔记本放在风扇旁录出来就是小的，而且它不可观测——没有办法问「为什么这段音频这么小」。

现在关掉它，在录音线程里做**有界自动增益**：

- **只放大不衰减**，上限 **+30 dB**（32×），目标峰值 **-1.9 dBFS**，硬限 0.95 保证 Int16 不回绕
- 判定按**本机底噪**而不是绝对电平：逐块跟踪 `floor`（下降快、上升慢），只有高出底噪约 8 dB
  的块才算语音。房间安静就多给，房间吵就少给，不需要手调
- **停顿期间不放大**，并让增益滑回 1。这一点是必须的：把 -50 dBFS 的房间嘶声抬 4 倍就会越过
  VAD 的 0.010 RMS 门限，分段器会把每个停顿都当语音，解码器于是对着静音空转

实测（同一段真人录音按比例衰减）：

| 场景 | 输入 | 输出 | 提升 |
|---|---|---|---|
| 正常音量 | -5.2 dBFS | -1.9 dBFS | +3.3 dB |
| 偏小 1/4 | -17.3 dBFS | -1.9 dBFS | +15.3 dB |
| 很小 1/10 | -25.2 dBFS | -1.9 dBFS | +23.3 dB |
| 极小 1/40 | -37.3 dBFS | -7.3 dBFS | +29.9 dB |
| 极限 1/100 | -45.2 dBFS | -17.7 dBFS | +27.5 dB |

正常音量几乎不动，偏小的被精确抬到 -1.9 dBFS。**RMS 同步抬升**（正常音量 -26.8 → -15.7 dBFS），
听感提升比峰值数字更明显。

> 增益在采集端，所以写进导出文件的本来就是提升后的 PCM，导出侧不需要再处理。

### 三、两个会让新用户直接卡住的 bug

**1. 全新安装永远下不了模型。**

首次加载模型时，`stt.load()` 先判定「模型不在盘上，允许一次性下载」，紧接着无条件调用
`apply_offline_env()`，把 `HF_HUB_OFFLINE=1` 塞进环境——那次下载必然失败。用户看到的是
「明明联网却报离线」，而应用内下载这条路径**从来就是死的**，只有 `fetch-model.bat` 能用。

现在只有模型已在盘上时才设离线标志；需要下载时改调 `apply_online_env()`，主动清掉上一轮
`setdefault` 留下的 `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE`。

**2. 后端选择不持久化，静默退回本地。**

模型选择存在 `models/choice.txt` 里，重启还在；后端选择却只认环境变量。换一个终端、或双击
exe 启动，就无声退回本地推理——界面仍显示你选的引擎，CPU 一路满载，而音频其实没离开本机，
只是被本机重算了一遍。

现在后端选择写进 `models/asr-backend.txt`（与 `choice.txt` 同构），写 `remote` 即要求远程，
缺 API Key 直接报错而不是降级。

### 四、远程定稿 + 本地字幕（混合模式）

实时字幕是唯一不适合走网络的一环：每 `LIVE_STEP_S`（0.6 秒）就要重传整段增长中的缓冲，
一句话上传几十遍。实测约 **46 次/分钟**，2000 次/日的免费额度约 **43 分钟**烧完，上行还是
O(n²)；远端慢时每步还要先等满 live 超时才回退，比纯本地更糟。

现在 `models/asr-backend.txt` 写 `remote` **只切定稿**：字幕留在本地 zipformer，定稿走
OpenAI 兼容端点。请求量从约 46 次/分钟降到约 1 次/分钟。

两套开关刻意分开：

| 开关 | 位置 | 效果 |
|---|---|---|
| 写 `remote` | `models/asr-backend.txt` | 只切定稿，字幕留本地 |
| `ECHONOTE_ASR_LIVE_REMOTE=1` | 环境变量 | 单独把字幕送上网络 |
| `ECHONOTE_ASR_REMOTE_ONLY=1` | 环境变量 | 本机不跑推理，字幕也上云 |

### 沿用 v0.12.0：边录边落盘、回放、sherpa 后端

- **OPFS 边录边落盘**：每 0.6 秒切一段 PCM 异步写盘，录音期间内存与时长无关；WAV / SRT / Markdown 流式导出。
- **回放 + 字幕 seek**：点时间戳跳转、波形同步高亮、30 秒窗口解码。
- **sherpa-onnx 流式后端**：zipformer int8，161 MB，rtf 0.126。
- **三轮尾音修复**：一句话最后 1–3 个字符曾被静默丢弃（`VAD_TAIL_KEEP_MS` 150ms→1000ms、
  峰值判静音、`covers_end` 比到 `duration_s`、`_SHRINK_GUARD` 前缀判据）。

| 指标 | v0.10 | v0.12.1 |
|---|---|---|
| 首条字幕出现 | 8.25 s | **2.8–3.0 s** |
| 停顿后定稿 | 2.2 s | **0.0–1.0 s** |
| 定稿精修 | 无 | 约 12 s（后台，不挡字幕） |

### 仍然没做到的

- 首字 2.8 s 卡在「2 秒缓冲 + 一次解码」的物理下限，A/B/C 档 p95 门禁仍未达标。
- 4 核机器上 whisper `medium` 定稿比实时慢，长录音时「精修中」会排队；换 sherpa 可以绕开。
- 没有代码签名证书，SmartScreen 会对未知发布者报警——这是「像桌面软件」最后一道门槛。
- 托盘图标、自动更新、文件关联还没做。
