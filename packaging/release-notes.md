## 下载后怎么用（Windows，不需要装 Python）

1. 下载 `EchoNote-v0.11.0-windows-x64.zip`（约 102 MB，不含模型）
2. 解压到**任意可写目录**，例如 `D:\EchoNote` —— 不要放在 `C:\Program Files`
3. **双击 `fetch-model.bat`** 准备模型（实时字幕 145 MB + 定稿 1.5 GB，自动走国内镜像，只需一次）
4. 双击 `EchoNote.exe`，浏览器自动打开，点麦克风开始录音
5. 关闭命令行窗口即退出

模型放进 `models\` 之后，**识别全程零联网**。需要硬保证不联网的环境：

```
EchoNote.exe --offline
```

### 出问题先跑自检

```
EchoNote.exe --self-test
```

逐项列出原生依赖（ctranslate2 / onnxruntime / av）、前端资源、模型状态。

## 这一版改了什么

### 边说边出字，这次是真的

v0.10 的根本问题是结构：VAD 把录音切成 3 秒一段，每段单独调一次 `transcribe()`，
而 Whisper 每次调用都会把音频补齐到 30 秒再编码。固定开销叠了十几倍，同一段
8.95 秒音频被切成三句后 RTF 3.9 —— 说一句要等十几秒。

v0.11 改成流式：VAD 只判断「有人在说话」，音频连续流入一个增长中的缓冲，
小模型按增量解码；句子结束由另一个更大的模型定稿，后台再精修一次。

同一台机器（i5-8300H，4 核 8 线程，纯 CPU）、同一段 8.95 秒音频：

| 指标 | v0.10 | v0.11 |
|---|---|---|
| 首条字幕出现 | 8.25 s | **2.8–3.0 s** |
| 说话过程中刷新 | 1.2 s 一次（且常常是空的） | 每 0.7–1.4 s 追加 |
| 停顿后定稿 | 2.2 s | **0.0–1.0 s** |
| 定稿精修 | 无 | 2.5–6.9 s（后台，不挡字幕） |

### 两个模型分工

- **实时字幕**：默认 `base`（145 MB），单次解码约 1.1 s，逐字追加。
- **定稿**：默认 `medium`（1.5 GB），每句结束后算一次（约 12 s），界面标
  「精修中」，结果以同一条 id 替换文本、时间轴不动，再标「已精修」。

`fetch-model.bat` 现在一次装这两个档；也可以 `--model` 指定，或 `--all` 全装。
界面模型标签会显示「实时 极速 · 定稿 快速」，两个角色分得很清楚。

### 准确率优先：定稿默认换 medium

同一段样本，用应用真实的定稿参数实测：

| 定稿档 | 耗时 | 字符错误率 |
|---|---|---|
| `small` | 3.7 s | 3.4%（「时时语音识别」） |
| `medium` | 12.1 s | **0.0%** |
| `large-v3-turbo` | 15.7 s | **0.0%** |

`medium` 与 `turbo` 并列满分，`medium` 快 23%，所以默认它。代价是 2.4 倍实时：
长篇说话时精修会排队，队列按音频秒数计（240 s），停止时按积压量等它落地。

另外修了两件会让准确率变差的事：定稿模型比实时模型小时不再精修（更差的
模型会覆盖更好的结果）；`tiny` 不再收到指令 prompt（它会把 prompt 复读出来，
实测既慢 44% 又更差）。

### 协议升到 v3

- `final` 新增 `stable` 字段：`false` 表示定稿模型还会改写它。
- 新增 `refine` 消息：与 `final` **同 id**，只替换文本。
- `status` 新增 `live_model` / `live_model_key` / `live_separate` / `live_ms`。

v0.10 的页面连 v0.11 的服务端会被握手拒绝并提示刷新，反之亦然 —— 这是故意的，
协议不兼容时宁可报错，也不要让时间轴悄悄错位。

### 实测踩到的两个坑（都已修）

- **置信度门限不能拍脑袋**：最初设 −0.85，把 1.2–2.0 s 缓冲里所有*正确*的字幕
  都丢了（真实读数在 −1.09 ~ −0.33），表现为「说了四秒才出字」。改成 −1.2。
- **收尾时白等**：`finish()` 会等一个在途解码，但那个解码覆盖不到句尾时纯属
  白等 1.6 s。现在只在它*可能*覆盖句尾时才等。

### 仍然没做到的

- 首字 2.8 s 卡在「2 秒缓冲 + 一次解码」的物理下限。想更快只能换更强的 CPU
  或更小的模型（`tiny` 的中文不可用）。
- 4 核机器上定稿仍比实时慢，长录音时「精修中」会排队；队列超过 3 句会丢弃并提示。
