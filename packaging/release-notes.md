# EchoNote v0.12.0 · 落盘与回放

> 技术预览（tech preview），不是 v1.0。录音与识别都在本机完成，音频不上传任何服务器。

## 下载后怎么用（Windows，不需要装 Python）

1. 下载 `EchoNote-v0.12.0-windows-x64.zip`（不含模型）
2. 解压到**任意可写目录**，例如 `D:\EchoNote` —— 不要放在 `C:\Program Files`
3. **双击 `fetch-model.bat`** 准备模型（实时字幕 145 MB + 定稿 1.5 GB，自动走国内镜像，只需一次）
4. 双击 `EchoNote.exe`，会打开一个**独立的应用窗口**（没有地址栏和标签页），点麦克风开始录音
5. 关闭应用窗口即退出；后台进程会在几秒后自行结束

模型放进 `models\` 之后，**识别全程零联网**。需要硬保证不联网的环境：

```
EchoNote.exe --offline
```

### 出问题先跑自检

```
EchoNote.exe --self-test
```

逐项列出原生依赖（ctranslate2 / onnxruntime / av）、前端资源、模型状态。

## 这一版改了什么

### 边录边落盘：录音不再吃内存

v0.11 把 PCM 全堆在 JS 堆里，录多久就涨多久。v0.12 换成一个 `AudioStore` 接口、
两套实现：

- **OPFS 落盘**（默认）：每个 Int16 帧按消息顺序同步写进浏览器 OPFS 的
  `*.pcm.tmp`，停止录音时再转成 `*.pcm`。**录音期间的内存占用与时长无关**，
  几小时的会议也不会把标签页撑爆。
- **内存降级**：隐私模式、没有 Worker、或浏览器缺少改名/流式写入能力时，
  自动改用内存存储，界面给一行提示。功能不残，只是长录音会占内存。

配套的几件事：

- **WAV 导出不再整段读入**：44 字节头 + PCM 分片直接拼成 Blob。落盘模式下峰值
  内存与录音时长无关；只有内存降级模式才是 2×。
- **停止后仍可继续**：连接中断后点「继续录音」接着写同一个文件，WAV 不会断成两截。
- **时长上限是软上限**：默认 90 分钟，`ECHONOTE_MAX_RECORD_MINUTES=0` 关闭；
  关闭后界面会说明现在是边录边落盘，内存只与回放窗口和降级模式有关。

### 回放与字幕联动

停止录音后可以回放本次录音（不用先导出）：

- 解码按 **30 秒窗口**进行，从点击位置附近起播，不把整段音频读进内存；
- 点任意一条字幕跳到该句并高亮当前句；
- 播放条激活时**空格键控制播放/暂停**，不再误触录音 —— 这是 v0.11 里最容易
  踩的坑：想暂停回放，结果开了新录音。

### 协议升到 v4

- 新增 `timing` 消息：每句报一次到「首字 / 定稿 / 精修」的毫秒数，精修完成后
  可能再来一条。**三个数两个原点**：`to_first_text_ms` 从语音起点算，
  `to_final_text_ms` / `to_refined_ms` 从关句时刻算；关句时刻比真实停顿晚约
  `VAD_HANGOVER_MS`（默认 900 ms）。详见 README「延迟口径」。
- `timing` 只是诊断信息，客户端忽略它除了少几个数字之外没有损失。

沿用 v0.11 的协议变更：`final` 带 `stable` 字段（`false` 表示还会被改写），
`refine` 与 `final` 同 `id` 只替换文本。协议不兼容时页面与服务端会互相拒绝并
提示刷新 —— 宁可报错，也不要让时间轴悄悄错位。

### 沿用 v0.11 的流式结构

VAD 只判断「有人在说话」，音频连续流入一个增长中的缓冲，小模型按增量解码，
句子结束再定稿、后台再精修。同一台机器（i5-8300H，4 核 8 线程，纯 CPU）、
同一段 8.95 秒音频：

| 指标 | v0.10 | v0.12 |
|---|---|---|
| 首条字幕出现 | 8.25 s | **2.8–3.0 s** |
| 停顿后定稿 | 2.2 s | **0.0–1.0 s** |
| 定稿精修 | 无 | 约 12 s（后台，不挡字幕） |

实时字幕默认 `base`（145 MB），定稿默认 `medium`（1.5 GB，同一段样本字符错误率 0）。
代价是精修约 2.4 倍实时，长篇连续说话时会排队，队列按音频秒数计（240 s）。

### 仍然没做到的

- 首字 2.8 s 卡在「2 秒缓冲 + 一次解码」的物理下限，A/B/C 档 p95 门禁仍未达标。
- 4 核机器上定稿比实时慢，长录音时「精修中」会排队；超过队列上限会丢弃并提示。
- Firefox / Safari 支持 OPFS 但没有 `move()`，停止录音时改为「流式复制 + 删旧文件」，
  收尾耗时与文件大小成正比（内存占用仍是常量）。两者都没有的浏览器直接降级内存。
