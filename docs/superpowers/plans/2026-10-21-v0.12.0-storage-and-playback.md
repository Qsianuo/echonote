# EchoNote v0.12.0「落盘与回放」实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 EchoNote 从「处理链路优秀、数据生命周期为空」的技术演示，升级为「录音可落盘、可回听、可定位」的可用工具，同时修掉四处已量化的性能缺陷与一处句首丢字缺陷。

**Architecture:** 前端引入一层 `AudioStore` 抽象（OPFS 分片落盘 + 内存/IDB 降级），把 `state.audioChunks` 这个 O(时长) 的 Int16Array 数组彻底移除，内存占用降到 O(1)；在 Store 之上叠一个 `PlaybackScheduler`（WebAudio 预排时间轴）实现无缝回放与字幕 seek。后端增加预滚缓冲修掉句首丢字，并增加逐段延迟埋点使后续优化可度量。

**Tech Stack:** Python 3.10+ / FastAPI / faster-whisper / pytest；原生 JS（零依赖零构建）/ OPFS / WebAudio / `node --test`。

**Spec:** 本计划实现两份分析文档中已确认的结论——
- `F:/realingo-study/对比分析报告.md` §7（EchoNote 性能风险点）、§9（P0/P1 建议）、§10（验收指标）
- `F:/Whispera-study/Whispera-架构研究笔记.md` §7（对 EchoNote 的可复用要点 7.1–7.6）

两份文档是设计依据，执行时与本文并行阅读。本文不重复其中的论证，只固化决策。

## 2. Review Focus

以下是本次改动最可能以「看起来对、用起来坏」的方式伤到用户的地方。每条在本计划中都有归属任务的测试。

1. **预滚音频插入后时间戳没有同步回退** —— 用户导出 SRT 时，字幕会早于对应声音最多 300 ms。预滚把音频前移了，`segment_start_frame` 必须同步前移，否则时间轴整体错位。
2. **OPFS 不可用时不降级而是抛错** —— 用户在 Safari 旧版、Firefox 旧版、或隐私模式打开，期望的是「还能录音、还能导出」，而不是录音按钮失效或控制台红字。
3. **录音中强关标签页留下 `.pcm.tmp`** —— 用户下次进入时，期望看到「上次有未完成的录音」，而不是把半截文件当成完整录音播放、或把损坏文件导成 WAV。
4. **回放 seek 到录音末尾附近** —— 用户拖动进度条到结尾，期望播完最后一点声音后正常停止，而不是静音、报错或无限读越界。
5. **空格键冲突** —— 空格已绑定录音/停止（`web/app.js:1338-1357`）。用户点开播放条后按空格，期望控制播放，而不是开始一段新录音。

### Task 2: `PlaybackScheduler` + `windowFor`

**Files:**
- Create: `web/playback.js`
- Test: `tests/js/playback.test.mjs`

**Interfaces:**
- Produces: `PlaybackScheduler.create({ leadS?: number }) -> Sched`；`sched.nextStartAt(currentTime: number) -> number`；`sched.advance(startAt: number, duration: number): void`；`sched.reset(atCurrentTime: number): void`；`sched.nextTime: number`（getter）。

- [ ] **Step 1: 写失败测试**

```js
// tests/js/playback.test.mjs
const P = require('../../web/playback.js');

test('first start is currentTime + lead', () => {
  const s = P.PlaybackScheduler.create();
  assert.equal(s.nextStartAt(10), 10.02);
});

test('second start lands exactly on the first end', () => {
  const s = P.PlaybackScheduler.create();
  const at = s.nextStartAt(10);
  s.advance(at, 3);
  assert.equal(s.nextStartAt(11), 13.02);   // 不重新加 lead
});

test('starvation re-syncs to now, not to the stale queue end', () => {
  const s = P.PlaybackScheduler.create();
  s.advance(s.nextStartAt(10), 1);          // 排到 11.02

test('reset rebases the timeline', () => {
  const s = P.PlaybackScheduler.create();
  s.advance(s.nextStartAt(10), 5);
  s.reset(30);
  assert.equal(s.nextTime, 30);
  assert.equal(s.nextStartAt(30), 30.02);
});

test('windowFor maps seconds to byte offsets', () => {
  const w = P.windowFor({ positionS: 100, windowS: 30, sampleRate: 16000, totalBytes: 8000000 });
  assert.equal(w.fromByte, 3200000);   // 100 * 16000 * 2
  assert.equal(w.toByte, 4160000);     // (100+30) * 16000 * 2
});

test('windowFor clamps at the end of the recording', () => {
  const w = P.windowFor({ positionS: 240, windowS: 30, sampleRate: 16000, totalBytes: 8000000 });
  assert.equal(w.toByte, 8000000);     // 不越界
  assert.ok(w.fromByte < w.toByte);
});

test('windowFor clamps negative positions to zero', () => {
  const w = P.windowFor({ positionS: -5, windowS: 30, sampleRate: 16000, totalBytes: 8000000 });
  assert.equal(w.fromByte, 0);
  assert.equal(w.toByte, 960000);
});

test('windowFor always returns Int16-aligned offsets', () => {
  const w = P.windowFor({ positionS: 1.00005, windowS: 30, sampleRate: 16000, totalBytes: 8000000 });
  assert.equal(w.fromByte % 2, 0);
  assert.equal(w.toByte % 2, 0);

```

- [ ] **Step 2: 跑测试确认失败**

Run: `node --test tests/js/playback.test.mjs`
Expected: FAIL —— `Cannot find module '../../web/playback.js'`

- [ ] **Step 3: 实现**

`nextStartAt(currentTime)`：`Math.max(currentTime + leadS, nextTime || 0)`。
`advance(startAt, duration)`：`nextTime = startAt + duration`。
`reset(atCurrentTime)`：`nextTime = atCurrentTime`。

`windowFor`：`bytesPerSecond = sampleRate * 2`；`fromByte = Math.max(0, Math.floor(positionS * bytesPerSecond / 2) * 2)`；`toByte = Math.min(totalBytes, Math.ceil((positionS + windowS) * bytesPerSecond / 2) * 2)`。两次除以 2 再乘回 2 是为保证 Int16 对齐。

**Interfaces:**

- Produces: `state.store` 对象，方法 `open(sessionId)`、`append(int16)`、`finish()`、`read(fromByte, toByte)`、`totalBytes`（getter）、`fallback: boolean`；供 Task 4/5 调用。

- [ ] **Step 1: 写 Worker**

`web/storage-worker.js` 收到 `{type:'open', name}` 时 `navigator.storage.getDirectory()` → `getFileHandle(name + '.tmp', {create:true})` → `createSyncAccessHandle()`，回 `{type:'opened'}`。收到 `{type:'append', buffer}` 时 `handle.write(new Uint8Array(buffer), {at: offset})`，`offset += byteLength`，每累计 32000 字节回一次 `{type:'progress', offset}`。收到 `{type:'finish'}` 时 `flush()` + `close()`，再由主线程 `move()` 改名为 `.pcm`。收到 `{type:'read', from, to}` 时读回并 `postMessage` 转出 ArrayBuffer。

- [ ] **Step 2: 接入 `app.js` 并删除旧数组**

- `state` 中删除 `audioChunks`，新增 `store: null`、`ledger: null`。
- `startRecording`：`state.ledger = AudioStore.PcmLedger.create({ maxBytes: MEMORY_BUDGET_BYTES })`；`state.store = await AudioStore.open(sessionId, {...})`；OPFS 不可用时 `open` 内部降级为 `MemoryStore` 并置 `fallback: true`，UI 显示一行提示（`textContent`），**不得抛错阻断录音**。
- `sendFrame`：`const verdict = state.ledger.accept(frame); if (!verdict.accepted) { warnOnce(); return; } state.store.append(frame); ws.send(frame.buffer);`（先 `ws.send` 再 `append`，因为 `append` 会转移 buffer 所有权）。
- `checkMemory`：改为 `if (state.ledger.overBudget) { ... }`，删除 `Wav.byteLength(state.audioChunks)` 调用。

- [ ] **Step 3: 容量预检与半截文件处理**

- 开始录音前 `await navigator.storage.estimate()`，`quota - usage < 300e6` 时提示并调用 `navigator.storage.persist()`。
- 启动时扫描 OPFS 根目录，发现 `*.pcm.tmp` 则提示「上次有未完成的录音（约 N 分钟），已保留为 .tmp，不参与播放与导出」。**不得自动删除，也不得当成完整录音**。
