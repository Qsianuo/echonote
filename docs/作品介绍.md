# EchoNote 声记 · 作品介绍

## 一、项目定位与核心功能

EchoNote 声记是一款**完全离线运行**的中文实时语音转写与中英互译工具。它解决的是一类很具体的问题：课堂上、讲座中、会议或设备巡检现场，人来不及记笔记，而把录音上传到云端又要担心内容外泄——尤其是涉及产线参数、客户信息、内部培训材料的时候。声记的做法是把识别和翻译全部放在本机完成：音频不出设备，断网照样能用，没有订阅费，也没有时长限制。

核心功能围绕"听得清、写得对、看得懂"三层展开。**实时转写**用流式模型边说边出字，延迟在一秒内，适合当字幕看；**定稿**在每段话结束后交给更准的模型重写一遍并补上标点，让最终稿可以直接当文档用；**同音术语纠错**针对专业词被听成同音词的老问题（"焦距"听成"脚距"、"曝光"听成"暴光"），在定稿后按读音把它改回来；**中英双向翻译**支持中文语音直接出英文、英文语音直接出中文，同样离线；最后是**导出**，一键生成 txt、Markdown 或带时间轴的 SRT 字幕，也可以回放录音并对照波形检查漏听的位置。

目标用户是学生与教师、需要整理访谈的记者与研究者、做现场记录的工程师，以及任何不方便把音频上传的场合。体验方式有三种：Windows 用户下载便携包双击即用，安卓用户安装 APK，也可以只用一个浏览器打开本地页面——手机扫码连上同一局域网后，手机当麦克风、电脑出字幕。

## 二、新增功能与三端形态

本次更新把"翻译"这条链路彻底打通，并补齐了三端之间原本不一致的能力。

**新增功能**有四项：一是离线中英双向翻译在网页端、桌面端、安卓端全部可用，译文与原文在同一行对照显示；二是同音术语纠错从 Python 侧移植到浏览器与安卓壳，两端用同一份术语表、同一套判据，同一段录音不会出现"一个纠正了、一个没纠正"；三是译文术语定向修复——在评测中确认小模型会把 `ring light` 直译成"戒指灯"后，新增一层只替换"实测错串"的修正，且必须英文原文真的含这个词才动手，避免误改；四是安卓端支持外部目录装模型，解决了签名包无法写入应用内部目录、导致正式用户装不上翻译模型的问题。

**三端形态各有取舍。**网页端最轻：无需安装，浏览器打开即用，还支持手机扫码当无线麦克风的局域网模式；代价是受浏览器后台策略限制，切到别的标签页容易被掐断，模型也依赖本机服务在跑。桌面端最完整：Windows 便携包解压即用，以无地址栏的应用窗口呈现，识别、翻译、导出、录音回放全部在本地完成，还负责给网页端和手机提供局域网入口，适合长时间、正式场合的记录。安卓端最自由：手机就是全部，语音识别和翻译都在端上推理，出门不带电脑也能用；代价是模型不进安装包，首次使用需要把翻译模型放到指定目录，且端上没有 Python，为了控制体积与延迟，中文分词改为纯 Kotlin 实现、解码用贪心而非 beam search。

## 三、技术栈

**Python 3.10 + FastAPI + Uvicorn + WebSocket** 组成桌面端的本地服务：浏览器与桌面窗口都在前端，音频以二进制帧经 WebSocket 上行，转写结果以 JSON 帧下行，协议版本独立编号，前后端不会因为版本不一致而静默出错。**sherpa-onnx** 承担两件事——流式 zipformer 负责边说边出字，SenseVoice-Small 负责定稿并恢复标点，两者混用兼顾了延迟与准确率；桌面端也可切换到 faster-whisper 系模型。**onnxruntime** 是推理底座，桌面端 1.23.2、安卓端 1.28.0，两套库在同一进程里符号版本互斥，最终给官方那份改 soname 才让"识别用 sherpa、翻译用官方 ORT"共存。**ctranslate2 + sentencepiece** 承载桌面的 Marian（opus-mt 77M）翻译，安卓端换成自行导出的 **ONNX int8** 三件套，并配一套手写的 unigram Viterbi 分词器替代原生 sentencepiece 库。前端是**原生 JavaScript（无框架）**加 **AudioWorklet**：音频在独立线程里做高通、陷波、低通、自动增益与 16 kHz 重采样，避开了主线程卡顿造成的丢帧。术语纠错用 **pypinyin** 取读音，在 Python 与 JS 两侧实现同一套判据。**PyInstaller** 把整个服务、前端与依赖打成单目录便携包；安卓侧用 **Capacitor + Kotlin 插件**把同一套网页资源装进原生壳，通过 JNI 调用 ORT。工程上以 **pytest（328 个用例）+ node:test（83 个用例）+ GitHub Actions** 守住行为契约，模型量化参数、词表映射、术语同步都有测试锁着，避免"改了模型忘了改代码"这类回归。
