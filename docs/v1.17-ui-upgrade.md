**分析（层级为什么是现在这样）**
`style.css:226-236` 的 `.layout` 是 `370px + 1fr`，两栏按面积就定了主次，而两栏共用 `.panel`（`:238`）同一套底/边/圆角；字号上 31 处 ≤12px、只有 5 处 ≥20px，标题 `:256` 是 14px 全大写弱色，正文 `:910` 15.5px，差 1.5px 不构成层级。于是"看哪块"全靠 `--accent` 的色块（27 处）和三层装饰（`.bg-grid` `:91`、`.bg-glow` `:102`、玻璃 `:242`）。

## 补测结果（2026-10-28 发版前，CDP 设备模拟实测）

上一轮沙箱起不了浏览器，这两条只有推演没有数字。发版前用 CDP
（`Emulation.setDeviceMetricsOverride`，DPR 2）补测，工具留在 `build/cdp-measure.py`。

| 宽度 | `scrollWidth` | 横向溢出 | 折叠 / 展开设置 / 无错误态 |
|---|---|---|---|
| 360 | 360 | 0 | 全部一致 |
| 390 | 390 | 0 | 三种状态均 0 |
| 768 | 768 | 0 | 全部一致 |

**触控目标**：`button/a/input/select/summary` 共 16 个，不达 44×44 的只剩 1 个——
设置区说明文字里的行内 GitHub 链接（41×15）。它属于 WCAG 2.5.5 明确豁免的
"句子中的行内链接"，不扩大。

### 补测中发现并修掉的两个真问题

1. **长错误串把控制面板撑到 462px**（真机上表现为横向滚动条）
   模型加载失败时，`#error-text` 里的 `（MaxRetryError('HTTPSConnectionPool…`
   是不可断的长 token，flex 子项默认 `min-width: auto` 让它以内容宽度为下限，
   连带把 `.control-panel` 从 390 撑到 462。修法：`.alert > span` / `.notice > span`
   加 `min-width: 0; overflow-wrap: anywhere`。
   修后 `#error-text` 实测 282px（容器 308px），`scrollWidth == clientWidth`，无裁切。
2. **3 个下拉框高 42px**，离 44 差 2px（靠 `padding` + 字号撑起来的高度）。
   修法：把 `.field select` 并入移动端断点已有的 44px 触控组（只在断点内生效，
   不带高桌面端下拉）。

> 注意一个测量陷阱：移动端模拟下若内容过宽，Chrome 会 `shrink-to-fit` 把布局视口
> 撑大（本次撑到 462），此时用 `innerWidth` 当基准会把溢出算成 0。基准必须取设备宽度。

## 与要求不符之处（已披露）

1. `grep -c '!important'` = 4，不是 0：`[hidden]` 1 处 + 两个 reduced-motion 块 3 处，属 a11y 功能代码，与标准 8 冲突时保留功能。

3. 工作区里 `app/stt.py`、`tests/conftest.py`、`tests/test_stt.py` 有**非本次**的未提交改动，我一个字节都没动，也未纳入提交。
